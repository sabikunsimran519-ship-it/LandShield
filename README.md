# LandShield — Citizen Pre-Purchase Land Risk Screening

A citizen-focused prototype for preliminary land-purchase risk screening. LandShield brings land information, ownership-related checks, mutation history, document checks, dispute indicators, khas land concerns, and acquisition-related risks into a single dashboard. The interface supports Bangla and English, with light and dark themes.

- **Repository:** https://github.com/sabikunsimran519-ship-it/LandShield
- **Hackathon:** LandTech Innovation Hackathon 2026
- **Problem Statement:** P5 — Citizen Pre-Purchase Verification
- **Project type:** Prototype / Decision-support screening tool

> **Important:** LandShield uses synthetic demonstration data. It does not provide official government verification, establish legal ownership, or replace professional legal advice.

## Overview

Land purchases can involve risks related to ownership, mutation history, missing documents, disputes, khas land, and government acquisition. Understanding these issues before purchasing land can be difficult for ordinary citizens.

LandShield demonstrates how a citizen-friendly screening interface can organize available information, apply predefined risk rules, explain potential warning signs, and present a preliminary screening report.

The system is intended to support informed decision-making. All results depend on the demonstration data and the rules implemented in the prototype.

## Features

- **Land record search:** Find demonstration records using a land reference ID.
- **Risk analysis:** Screen for ownership, document, dispute, khas land, and acquisition-related concerns.
- **Risk scoring:** Present an overall numerical score and a LOW, MEDIUM, or HIGH classification.
- **Mutation history:** Display available demonstration history.
- **Document checks:** Identify missing information and potential document-related warnings.
- **Land map:** Provide an illustrative map interface for the prototype.
- **What-if simulator:** Explore hypothetical scenarios and their possible impact on screening results.
- **Screening report:** Present available information and identified warning signs.
- **Bilingual interface:** English and Bangla.
- **Display themes:** Light and dark modes.

The map is illustrative and does not represent verified cadastral boundaries. Screening scores and classifications are generated by the project's implemented rules, not by an official government risk assessment.

## Technology Stack

- **Frontend:** HTML, CSS, JavaScript
- **Frontend server and API proxy:** Node.js
- **Backend:** Python, Flask
- **Database:** SQLite
- **Risk engine:** Rule-based screening logic
- **Development tools:** Visual Studio Code, Git, GitHub

## Architecture

The application uses a browser-based frontend, a Node.js server/proxy, a Flask backend, and an SQLite database.

1. The user interacts with the LandShield dashboard.
2. The frontend sends requests through the Node.js server.
3. The Flask backend processes land information and applies the screening rules.
4. SQLite provides the demonstration records and related history.
5. The backend response is presented in the dashboard.

## Run locally

### Prerequisites

Install:

- Python 3
- Node.js and npm
- Git (optional if the project is already on your computer)

### 1. Get the project

```bash
git clone https://github.com/sabikunsimran519-ship-it/LandShield.git
cd LandShield
```

Alternatively, open your existing LandShield project folder in Visual Studio Code.

### 2. Install Python dependencies

Create a virtual environment from the project root:

```bash
python -m venv venv
```

Activate it on Windows:

```bash
venv\Scripts\activate
```

Install dependencies:

```bash
pip install -r requirements.txt
```

If `python` is not recognized, try `py` in its place.

### 3. Start the Flask backend

In the first terminal, run:

```bash
python app.py
```

The backend is expected to be available at:

`http://127.0.0.1:5000`

Keep this terminal running.

### 4. Start the Node.js server

Open a second terminal in the project root:

```bash
node server.js
```

The frontend is expected to be available at:

`http://127.0.0.1:3000`

Keep this terminal running too.

### 5. Open the application

Visit:

http://127.0.0.1:3000/

Both servers must be running for features that depend on the backend API. If a port is already in use, check whether the relevant server is already running.

## Demonstration records

The prototype includes synthetic records for demonstrating different screening outcomes.

- **DEMO-001:** A higher-concern example with an active dispute indicator. The previously tested example produced an overall score of 47/100 (MEDIUM), while the critical dispute indicator triggered a HIGH RISK screening outcome.
- **DEMO-002:** A lower-concern example without the modeled dispute, khas land, and acquisition concerns in that demonstration record. The previously tested example produced a score of 14/100 (LOW).

These scores describe the example records and the behavior of the implemented rules. They are not findings about real properties.

A critical warning can affect the final screening outcome even when the numerical score falls within the MEDIUM range.

## Data sources, privacy, and limitations

- The prototype uses synthetic demonstration data.
- It does not claim to connect to or verify records against official government databases.
- Map visuals are illustrative, not official land boundaries.
- Risk results depend on the information stored in the selected record and the implemented rules.
- Missing or inaccurate input can affect the screening result.
- A LOW RISK classification does not guarantee that a property is safe to purchase.
- Users should verify documents and relevant records through authorized channels and consult qualified legal professionals before purchasing land.
- No real personal land-record data should be added to the public repository.
